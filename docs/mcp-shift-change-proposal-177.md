# MCP シフト変更案（#177）

`propose_shift_change` は確認済みの事業所・シフト・スタッフ ID と、タイムゾーン付き開始・終了日時を受け取り、現在のシフト、指定した1人と日時の案、別シフトとの重複、利用者の担当登録を返す。対象シフト自身は重複から除く。取消・削除済みは対象外、隣接する時間は重複しない。日時は最大24時間。担当登録がない場合も適合性を断定せず、勤務予定、移動、資格、区間や他の担当者への影響を要確認とする。

この結果は提案であり、シフト、担当、Google予定を変更しない。区間の再配置や他の担当者の変更案は生成しない。変更実行前に別途最新状態を確認する。シフトと人物検索の事業所設定、OAuth・所属、シフト全件閲覧権限を DB で確認し、部分閲覧は拒否する。削除・取消済みや他事業所の対象は返さない。

Context7 は利用枠上限のため、2026-10-29 に Supabase の [DB関数](https://supabase.com/docs/guides/database/functions)・[RLS](https://supabase.com/docs/guides/database/postgres/row-level-security) 公式資料を参照した。実環境への migration・MCP 関数配備・実認証試験・機能有効化は別途必要。
