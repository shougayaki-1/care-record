# AUTH-04: Google一括削除の認証中断時に成功IDのみ論理削除する

Source finding: `docs/audits/authentication.md` / Severity: P2

## Background
Google予定とCareRecordシフトの削除結果を一致させ、認証中断時の未処理行を誤って論理削除しない必要がある。

## Current behavior
20件chunkの処理中にauth errorでbreakすると、`failedIds`には失敗した1件だけが入り、呼出し側が残りを削除成功扱いし得る。影響は失敗chunk内の後続最大19件。

## Root cause
逐次処理のsuccess/failed/unprocessed結果契約と、論理削除へ渡すID集合の契約が一致していない。

## Scope
`processShiftsSequential`、`deleteShiftsBatch`、20件chunk UIの結果受渡しを対象に、成功IDだけを削除対象にする。

## Out of scope
Google同期方式の全面変更、chunkサイズの一律変更、`repairGoogleCalendarSync`の廃止。

## Security considerations
問題はConfirmedだがsilent failureではない。既存repair pathを維持し、手動復旧とGoogle側event残存期間を利用者へ明示できる結果にする。

## Acceptance criteria
- auth error時に未処理IDが論理削除されない。
- 成功したGoogle削除とCareRecord logical deleteのID集合が一致する。
- 後続最大19件を含むchunk回帰で、失敗・未処理・成功を個別に表示/記録できる。

## Required tests
2件目auth失敗、先頭/末尾失敗、rate limit/transient、複数chunk、repairGoogleCalendarSyncによる復旧試験。

`src/app/actions/shifts/googleSyncInternal.ts`, `src/app/actions/shifts/crud.ts`, `src/app/app/shifts/manage/page.tsx`, `src/app/actions/shifts/googleSync.ts`
