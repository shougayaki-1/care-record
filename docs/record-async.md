# 記録の非同期操作

Issue #33。#32 のフォーム・アクション配置を維持し、#34 の `commitRecordChange` をそのまま使う。

## 共通ルール

- `useAsyncRecordAction` は確認ダイアログを開く前に同期的にロックする。処理開始時に前の通知・エラーを消す。
- 処理中は既存 `AppButton` の loading / disabled / aria-busy を使い、入力・閉じる・再実行を止める。成功／失敗を共通 ToastProvider で通知する。
- finally でロック・pending を解除する。画面の組織・記録 scope が変わった場合や unmount 後の完了では、古い成功通知や遷移を実行しない。
- 失敗は入力を保持して手動再試行可能にする。失敗通知に加え、フォーム／確認ダイアログ内にもエラーを保持し、トースト消去後も確認できるようにする。自動再送は追加しない。通常記録とAI下書きは既存 API の idempotencyKey を同じ入力の失敗後にも再利用し、入力変更・成功後には更新する。
- 永続化後の再取得は引き続き `commitRecordChange`。再取得失敗を保存失敗として扱わず、保存を再実行しない。

## 経路ごとの完了処理

- 通常記録: 下書きは編集を継続。送信は記録一覧へ。閉じる前の下書き保存に失敗した場合は確認ダイアログを維持する。手動保存・AI読み取り中は新しい自動保存タイマーを停止する。
- 内勤: 成功後のみ全入力を初期化して閉じる。失敗時は件名・担当・日時・時間・メモと保存キーを保持する。入力編集・成功・入力破棄後は新しいキーを使う。応答喪失後の同一入力の再試行は同じ記録 ID を返す（DB契約は [内勤保存の冪等性](internal-work-idempotency.md)）。
- 通常画面のAI読み取り: 全ストリーム成功後に入力へ反映。途中の結果の後で失敗しても既存入力を上書きしない。成功後にファイルをクリアして閉じる。処理中は親フォームの保存も停止する。
- AI一括読み取り: グループ単位の進捗を維持。再読み取り失敗時は既に修正した行を保持する。初回の部分結果は保持し、原本照合の対象にする。
- AI一括下書き: 行ごとの成功・失敗を保持し、一つの集計通知を表示。成功行は再送しない。失敗行は内容修正または同じ入力で再試行できる。全体例外でも行の saving を解除する。
- 受信AI候補: 承認・却下に同じロック・通知を使用。承認失敗時は確認ダイアログと修正内容を維持し、成功後のみ候補を除く。外部AIからの受信処理は変更しない。

## 検証

- hook: StrictMode、多重呼び出し、確認キャンセル、エラー解除、再試行、scope変更／unmount、冪等性キー。
- 画面: 通常の失敗後下書き保存、内勤の入力保持・成功後リセット、AIストリームの遅い失敗と再試行、一括の部分成功・失敗行のみ再送・既存フィード通知。
- Storybook: 共通通知の置換・消去、AI確認行の処理中操作停止・保存失敗。
- Playwright: 専用ローカルSupabaseで通常・内勤・受信AI承認の保存→フィード、既存の狭幅レイアウト。外部AI呼び出しは行わない。
