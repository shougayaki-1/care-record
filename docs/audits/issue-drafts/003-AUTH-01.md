# AUTH-01: セッション絶対期限のrolling再発行を防止する

Source finding: `docs/audits/authentication.md` / Severity: P1

## Background
採用済みのabsolute 30日・idle 24時間の保証を、活動登録やtoken refreshで延長できないことが必要である。

## Current behavior
`ensureSessionActivity` が既存sessionへ `last_activity`、`absolute_expires_at`、`revoked_at` をupsertし、absolute期限を毎回30日先へ再設定する。`touchCurrentSession`とmiddleware bootstrapには既存防御がある。

## Root cause
欠落行補完の経路が既存行の不変条件を保護せず、絶対期限を再発行している。

## Scope
`ensureSessionActivity`の既存行・新規行の契約、呼出し元、期限・失効不変条件を整理する。

## Out of scope
absolute/idleの採用値変更、`touchCurrentSession`やmiddlewareの無関係な改修、MFA導入。

## Security considerations
既存sessionのabsolute期限とrevoked状態を延長・復活させない。revoked session resurrectionは別途runtime検証し、global signOut後のaccess tokenで`supabaseAdmin.auth.getUser()`の挙動を確認する。

## Acceptance criteria
- TOKEN_REFRESHED、INITIAL_SESSION、SIGNED_INの各経路で既存absolute期限が延長されない。
- 既存`revoked_at`がnullへ戻らない。
- 新規行の登録と既存行の活動更新が明確に区別される。

## Required tests
同一sessionの各イベント前後の列比較、期限直前/経過、失効行、global signOut後access tokenのruntime試験。

## Relevant files
`src/app/actions/auth.ts`, `src/context/WorkspaceContext.tsx`, `src/utils/supabase/auth.ts`, `src/utils/supabase/middleware.ts`
