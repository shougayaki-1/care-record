# GAP-01: シフト更新のPermission / RLS / 成功判定不整合を修正

Source finding: `docs/audits/feature-gaps.md` / Severity: P1

## Background
シフト時間変更・取消は業務判断と監査の基礎であり、利用者へ示す成功結果はDB実態と一致する必要がある。

## Current behavior
`permissions.ts` は `shifts.edit='assigned'` を許可するが、DB UPDATE policy は `edit='all'` を要求する。Actionはupdate結果を十分に検証せず成功auditと成功responseへ進み、UIは成功toastを表示し得る。RLSによる0-row UPDATEは必ずしもerrorにならない。

## Root cause
Server Action、permissions、RLS、audit、UIの成功契約が別々に定義され、影響行0とDB errorを同じ失敗契約で扱っていない。

## Scope
`updateShiftTimeOnly`、`toggleCancelShift`を中心に、Server Action・RLS・permissions・audit・UI結果・regression testを一つのIssueで整合させる。

## Out of scope
Google同期の再設計、無関係なshift refactor、他機能の権限モデル変更。

## Security considerations
tenant boundaryとRLSを維持し、UI表示だけでなくDB結果を成功条件にする。assigned/allの許可範囲を仕様に合わせ、他組織・未割当行を更新できないことを確認する。

## Acceptance criteria
- assigned/allの許可・拒否がpermissionsとRLSで一致する。
- DB errorまたは影響行0では成功audit、成功response、成功toastを返さない。
- 実更新時だけ成功auditと成功表示になり、監査内容がDB実態と一致する。

## Required tests
Actionのerror/0-row/成功モック、RLSのassigned/all/他組織回帰、UIのtoastとrevert、成功・失敗auditの検証。

## Relevant files
`src/app/actions/shifts/crud.ts`, `src/utils/permissions.ts`, 現行shifts UPDATE policy migration, `src/app/app/shifts/manage/page.tsx`, `src/utils/supabase/audit.ts`
