# AUDIT-01: owner移管操作を監査ログへ記録する

Source finding: `docs/audits/authentication.md` / Severity: P2

## Background
owner移管は重要操作であり、実行者・対象組織・新owner・結果を事後追跡できる必要がある。

## Current behavior
`transferOwner` と `transfer_owner_atomic` は成功しても対応するaudit eventを記録しない。

## Root cause
認可・step-up処理と監査記録の責務が接続されていない。

## Scope
owner移管の成功、拒否、例外について、既存audit_events契約へ記録する経路を整える。

## Out of scope
AUTH-02のstep-up強制、監査基盤全体の再設計、他操作の一括改修。

## Security considerations
`.claude/rules/security.md`の重要操作監査要件に従い、secretやtokenを記録しない。tenant boundaryとactor identityを監査側でも混同しない。

## Acceptance criteria
- 成功時にactor、org、対象旧owner/新owner、結果を追跡できる。
- 認可拒否・RPC例外も既存方針に沿って記録または明確に扱う。
- AUTH-02の認可結果と監査結果が矛盾しない。

## Required tests
成功、非owner、権限不足、別tenant、RPC例外、監査保存失敗時の試験。

## Relevant files
`src/app/actions/organization.ts`, `supabase/migrations/20260716000015_org_deletion_rls.sql`, `src/utils/supabase/audit.ts`, `.claude/rules/security.md`
