# MCP スタッフ・利用者検索（#173）

`search_people` は事業所 ID、`kind`（`client` / `staff`）、名前の部分一致を指定する。最大100件、offsetでページングし、`has_more` を返す。候補は ID、氏名、登録日（JST）のみ。アーカイブ・削除済みは返さない。複数候補は自動確定せず利用者に選択を求める。同名かつ同日登録など区別できない場合は、別の正規の業務画面で確認する。ID は識別子であり本人確認の根拠ではない。

事業所別の人物検索設定は既定 off で、シフト参照・候補送信とは独立する。`enable_mcp_person_search` は integrations 管理権限と提供条件6項目を要求し、変更と監査を同一トランザクションで行う。提供条件の確認までは有効化しない。`disable_mcp_person_search` で停止できる。管理画面は今回追加しない。

直接 RPC を含め毎回 OAuth 有効性と事業所所属を確認する。利用者には既存の `can_access_client`、スタッフには既存 RLS と同じ事業所所属境界を適用する。RLS と permissions 定義は変更しない。外部 AI の契約・地域・保持・二次利用・利用者説明は未確認であり、本番の実データ提供は未承認。
