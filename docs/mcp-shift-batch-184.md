# MCP による複数シフト変更案（#184）

`prepare_shift_updates_batch` は最大10件の既存シフトの変更案をまとめます。各案は単件変更と同じ権限・事業所・対象・OAuth・有効化設定を検証し、変更前後と表示名を固定します。案の作成ではシフトを更新しません。事前に既存の重複・担当登録チェックを区間ごとに使い、結果を確認画面に表示します。担当者・区間のチェックは合計100件までです。勤務予定、休暇、移動時間、資格、案どうしの影響などは引き続き人が確認します。

本人がアプリ上で各案の内容と件数を確認し、変更する案だけ選びます。MCP 接続から確定はできません。確定時には単件変更処理を再利用し、本人のセッションと OAuth 接続、現在の権限、事業所別停止設定、固定された内容・参照名、対象の変更、担当者と利用者の予定の重複を再検証します。選択外は更新されず、競合・期限切れ・変更済みの案は失敗件数に含めます。成功ごとに既存監査を書き、Google 同期を試みます。同期できなかった場合は既存の未同期状態を維持します。

新しい権限や RLS policy は追加しません。非公開テーブルは RLS を有効にし全アプリロールを revoke しています。各シフトの既存 RLS と `permissions.ts` の権限定義を変更せず、単件変更と同様に view/edit の `all` と対象の認可を DB で確認します。新規 RPC は一括案作成のみを MCP ロールに、照合・確定のみを authenticated に許可します。

2026-11-15: Context7 で PostgreSQL 17 の PL/pgSQL 例外ブロックとロック解放を確認しました。ローカル DB のトランザクションで合成データを使用し、提案のみ・選択範囲・競合・監査・既存セキュリティテストを確認しました。実際の AI クライアント・外部 Google 同期は未検証です。
