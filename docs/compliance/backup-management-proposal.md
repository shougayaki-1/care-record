# 事業所向け提案書：提供記録バックアップと即時提示体制

作成日: 2026-06-25

## この提案書の目的

Care Record に記録された提供記録データを安全に保管しつつ、万一本番システムが停止していても実地指導時に必要な記録を短時間で提示できる体制を整えるための提案です。

想定する読み手は、以下の両方です。

- **経営者** — 何を守るのか、いくらかかるのか、どこまで備えるのかを判断する
- **IT担当者** — どのクラウドに、どのデータを、どの期間、どの方式で保存するかを設計する（詳細は別紙「IT実装ガイド」参照）

## 背景：なぜバックアップが必要なのか

Care Record は事業所の中核的業務システムです。記録されたデータは以下の場面で必要になります。

### 1. 実地指導への対応

都道府県や市区町村による実地指導時に、利用者ごとの提供記録を「その場で」提示する必要があります。

- **課題** — 本番システムが停止していたら、記録を提示できず、指導で不利になる
- **対策** — 本番システムとは別の場所に記録を常置し、停止時でも取り出せる体制

### 2. 監査・事故対応

内部監査や、利用者対応の事故が発生した際、当時の記録を確認します。

- **課題** — システム故障で過去データが失われたら、対応ができない
- **対策** — 長期間（法定要件や契約に基づいて）、改ざんできない形で保管

### 3. 法定・契約要件への対応

介護保険法、障害者総合支援法などの指針では、記録の保存期間が定められています（一般的に 2-5 年）。

- **課題** — 法定要件を満たしていないと、指導時に指摘される
- **対策** — 保存年限を明確にして、改ざん防止のロック機能で守る

## 結論：推奨構成

**Google Cloud Storage を使った二層構成** をお勧めします。

| 層 | 用途 | 保存場所 | 保存クラス | 保存期間 | 料金感 |
|---|---|---|---|---|---|
| **第1層：検索・提示** | 実地指導など、日常的な提示 | Google Cloud Storage | Standard | 直近 90 日 | 非常に低コスト |
| **第2層：保全** | 監査、事故対応、法定要件 | Google Cloud Storage | Archive | 7 年を推奨 | 月額 $1-3 程度 |

### この構成のメリット

✓ **本番停止時も即座に対応可能** — 検索用データは常に別保管地にあり、オフィスのシステムが止まっていても PC から取り出せます

✓ **改ざん防止が組み込まれている** — Archive 側は Bucket Lock により、保存期間中は削除・短縮ができない仕組みを実現

✓ **実地指導で「復元作業」が不要** — 毎回バックアップから復旧する手間がなく、常に最新データにアクセス可能

✓ **費用が非常に抑えられている** — 画像を除いて、表データだけなら月額数百円～数ドル程度で実現可能

✓ **スケーラブル** — データが増えても、ストレージ料金は線形に増える（急増しない）

## 保存対象と除外

### 保存対象

以下の Care Record データを毎日エクスポート・保管します。

- **固定項目**
  - 利用者名
  - 記録日、サービス開始・終了日時
  - 担当者
  - 提供時間、移動時間
  - 承認状態、削除状態

- **可変項目**
  - 記録フォームの本文
  - 加算、備考
  - テンプレートごとの入力項目

### 除外対象（今回は非対象）

- **画像・写真** — ファイルサイズが大きく、料金への影響大。必要に応じて別途検討
- **システム設定** — 別途「復旧用設定情報」として、1年保管

## 保存期間と根拠

### 推奨：7 年

事業運営上の保守的な値として 7 年を提案します。

| 法令・指針 | 保存期間 | 備考 |
|---|---|---|
| 介護保険法（訪問介護など） | 2 年 | 指定基準により異なる |
| 障害者総合支援法 | 2～5 年 | サービス種別に応じて |
| 自治体ガイドライン | 3～5 年 | 都道府県で異なる場合あり |
| 一般的な企業記録 | 7 年 | 税務・民事時効を考慮 |

**最終的には、貴施設の法務・コンプライアンス担当者に確認してください。** 提案値を変更することは可能です。

Archive ストレージから取り出すときは、取得料金がかかります。

**通常の実地指導対応では Standard から取り出すため、取得料金は発生しません。**

## 運用体制

### スケジュール

| 時期 | 内容 | 担当 |
|---|---|---|
| **実装開始後、1-2 周** | Google Cloud セットアップ、Care Record エクスポート機能追加 | IT 担当者 |
| **実装完了後** | 日次自動バックアップ開始（毎日午前 1 時） | 自動化 |
| **毎月初週** | 復旧テスト実施、正常動作確認 | IT 担当者（30 分程度） |
| **毎年一回** | 保存期間の見直し、コスト最適化の検討 | 経営者 + IT 担当者 |

### 日常的な運用

- **自動化**されているため、通常は手作業がありません
- **毎月 1 回、10 分程度の復旧テスト**で、実際に「取り出して読める」ことを確認します
- **エラーが発生した場合**は、IT 担当者に通知が届き、対応します

### 月次復旧訓練の目的

実地指導や事故が起きたときに「あわてずに」対応できるよう、毎月テストしておきます。

- 10 分以内に必要なデータを取り出せるか
- 取り出したファイルが読める状態か
- データの漏れはないか

を確認します。詳細な手順は IT 担当者が別途案内します。

## AWS との比較

AWS S3 でも同等の構成は可能です。ただし、Google Cloud の方が、以下の点で有利です。

| 観点 | Google Cloud | AWS |
|---|---|---|
| **即時提示** | Standard なら取得料金 0、ミリ秒アクセス | S3 Standard-IA で取得料金あり、または Glacier Instant Retrieval で 90 日最低保存期間 |
| **長期保全** | Archive なら低コスト、ミリ秒アクセス | Glacier Flexible Retrieval は時間単位の復元待ち、複雑 |
| **改ざん防止** | Bucket Lock がシンプル | S3 Object Lock は Versioning を前提に WORM 実装、複雑 |
| **運用難度** | ライフサイクル管理が直感的 | ストレージクラス選択が複雑 |

**既に AWS 契約がある、または社内標準がある場合は、AWS での実装も検討します。** ただし本提案では GCP を推奨します。

## 経営上のメリット

### リスク軽減

✓ 本番システム停止時の対応力が上がり、実地指導への対応が確実になります

✓ 万一のデータ喪失に備え、事業継続性が高まります

✓ 改ざん防止ロックにより、不適切な削除から保護されます

### コンプライアンス

✓ 法定保存期間を明確に満たします

✓ 監査時に「バックアップ体制がある」と説明できます

### 費用対効果

✓ 月額 $1-3 程度（実施規模による）で実現可能

✓ 初期費用は IT セットアップのみ

✓ 以降の運用コストはほぼゼロ（自動化）
