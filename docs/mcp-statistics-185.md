# MCP 月次集計（#185）

`get_monthly_statistics` は JST の年月を指定し、統計画面と共通の計算で予定・実績・サービス・移動・内勤時間と未承認・差戻し件数を返す。担当者別の合計は同じ訪問を複数担当者にそれぞれ加算し、内勤も含む。利用者別の合計には内勤を含めない。件数はそれぞれの画面行の合計であり、事業所内の重複しない記録件数とは限らない。時間や状態の扱いは既存統計画面の定義に従う。

事業所・機能別の集計設定は既定停止で、連携管理者が提供先、処理条件、地域、保持、二次利用、利用者説明の6項目を確認して有効化する。設定操作と監査は同じトランザクションで確定し、監査に自由記述を含めない。既存の記録参照・シフト参照の設定も必要。DB は OAuth、事業所所属、帳票管理権限、事業所全体の記録・シフト閲覧権限を再確認する。画面の取得上限に合わせ、各対象が1,000件を超える場合は部分集計せず拒否する。環境の PostgREST 上限がこれより低い場合は画面との一致を別途確認する。

MCP の出力は合計のみ。ただし発行済み MCP トークンで直接呼べる `get_mcp_kpi_source` は、同じ権限・停止制御の下で、計算用に個別の時刻・状態・担当人数・サービス時間・移動時間・内勤時間を返す。氏名、ID、本文は含めないが、これらも機微な業務情報として提供条件に含める。中間データをログへ出さない。MCP クライアントと外部 AI 側の保持・利用条件は個別に確認する。

合成ローカル DB の実 RPC 応答を画面と同じ集計関数に渡し、両タブの合計を照合した。期間やデータ状態による差がないことの網羅的な証明ではない。実環境への migration・MCP 関数配備、実認証試験と事業所の有効化は別途行う。Context7 は 2026-10-30 に利用枠上限だったため、既存実装と前回確認した Supabase の共有モジュール資料を参照した。
