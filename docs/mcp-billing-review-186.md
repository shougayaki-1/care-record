# MCP 請求前の確認候補（#186）

`review_billing_records` は JST サービス日で絞った記録を最大20件ずつ検査し、承認状態と既存の記録品質検査から要確認の理由を返す。本文やフォームの値は返さない。返される件数は候補だけで、`scanned`、`has_more` と `offset` は検査した記録のページを示す。空の候補一覧でも `has_more` が true なら次ページがある。各取得で既存の OAuth・事業所・記録権限と事業所別設定を検査し、予定との差はシフト閲覧が許されている場合だけ比較する。

`list_billing_unrecorded_shifts` は期間に重なる、取消されていない閲覧可能な予定から、記録との紐付けがない予定や、直接記録が紐付いていない区間を候補として最大20件ずつ返す。隠れた記録を存在しないと誤認しないよう、事業所全体の記録閲覧権限と記録・シフト両方の機能設定を必須とする。一般のシフト単位記録や複数シフトの紐付けでも区間は候補になりうるため、未入力や請求不可と断定せず確認する。予定と記録のページは独立している。削除済み、取消済みの予定は対象外。期間内の将来予定も含む。

いずれも確認支援であり、請求・法令判断・記録・承認状態を変更しない。現在のフォームに基づく検査や分割記録、期間境界などは人が確認する。取得は複数リクエストなので、同時更新によりページ間で内容が変わることがある。MCP 関数の配備、実認証試験、提供条件の確認と機能有効化は別途必要。

2026-10-30 に Context7 で Supabase の DB 関数の `security definer`、`search_path` と実行権限を確認した。RLS ポリシーと `permissions.ts` は変更せず、既存の閲覧スコープと対象行の認可を RPC 内で照合する。
