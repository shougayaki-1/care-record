# Googleカレンダーの再認証が頻発する場合

## 約7日ごとに切れる

Google Cloudで、このアプリの `GOOGLE_CLIENT_ID` に対応するプロジェクトを開き、
Google Auth Platform → 対象（Audience）の公開ステータスを確認する。
ユーザーの種類が「外部」で公開ステータスが「テスト中」の場合、Calendarスコープを
含む更新トークンは7日で失効する。アクセストークンの自動更新や同期修復では解消しない。

本番利用の場合はGoogleの公開・検証要件を確認して公開ステータスを変更したうえで、
CareRecordの設定 → Googleカレンダー連携 →「Googleを再認証」から認証を更新する。
既存のカレンダーを利用できる同じGoogleアカウントを選ぶ。「連携を解除」は不要。
公開済みでもユーザーによる許可の取り消しや管理者ポリシー等による失効はありうる。

公式仕様: https://developers.google.com/identity/protocols/oauth2#expiration

## 間隔が不規則な場合

設定画面の接続状態とサーバーログの分類を確認する。トークン・クライアントシークレットを
ログや問い合わせに貼り付けない。

| 状態 / 分類 | 確認すること |
| --- | --- |
| 再認証が必要 / `auth` | `invalid_grant` / `invalid_token` / 401。許可の取り消し、OAuth公開状態、Google Workspaceのポリシー、同じユーザー・OAuthクライアントでのトークン発行数上限を確認する。 |
| アクセス権を確認 / `forbidden` | 403。連携したGoogleアカウントが既存カレンダーにアクセス・編集できるか確認する。 |
| 連携設定を確認 / `misconfigured` | OAuthクライアントID・シークレット・リダイレクトURIとCalendar APIの有効化を確認する。ユーザーの再認証だけでは解消しない。 |
| 一時的に接続できません / `transient`・`rate_limit` | ネットワーク、Google側の障害、利用制限を確認する。接続確認では回数を制限して自動再試行し、解消しなければ時間をおいて再試行する。 |
| カレンダー要確認 / 404 | カレンダーの削除や、別アカウントでの認証によりアクセスできない状態を確認する。 |

## 実装上の保護

- Google公式ライブラリが保存済みの更新トークンを使ってアクセストークンを更新する。
- 権限エラー・OAuth設定エラーをトークン失効と区別する。
- 再認証時に既存カレンダーを読み取れない場合、保存済みトークンとカレンダーIDを維持する。
- 同期修復の開始時点で通信が失敗した場合も、成功と表示しない。

この変更はGoogle側で失効した更新トークンを復活させるものではない。
Google Cloudの公開設定と本番ログは、アプリのユニットテストとは別に確認する必要がある。
