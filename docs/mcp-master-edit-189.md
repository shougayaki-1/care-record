# MCP のマスタ変更案（#189）

AI アプリは利用者名、またはスタッフ名・雇用形態・勤務形態の変更案を作れます。名前は1〜100文字、雇用形態は常勤・非常勤、勤務形態は兼務・専従に限定します。対象IDや変更内容を推測せず、本人がアプリで事業所、対象ID、変更前後を確認するまでは更新しません。アカウントの紐付け、担当、ロール、削除、その他の項目は変更できません。

事業所ごとに初期状態は停止中です。連携管理者が提供条件を記録して有効化し、停止できます。利用者・スタッフ検索も別途有効である必要があります。提案者には対象事業所の利用者またはスタッフ管理権限を要求します。保存時は本人のブラウザーセッション、元の OAuth 接続、管理権限、停止設定、事業所と対象の状態、固定された変更前の値を再確認します。失効・担当外・対象変更・期限切れは拒否し、更新と既存の監査イベントを同じトランザクションで確定します。

新規テーブルは非公開 schema で RLS を有効化し、アプリロールの直接アクセスを禁止しています。既存 RLS policy と `permissions.ts` は変更せず、既存の `management.clients` / `management.staffs` と対象認可を DB で再検証します。外部 AI の処理条件を確認するまで利用を有効化しないでください。

2026-11-15: Context7 で Supabase の `security definer`、`search_path`、関数の実行権限を確認しました。ローカル DB 上のロールバック付き検証で、提案のみ、正常確定、他事業所・無権限、競合、停止・失効、監査失敗時のロールバックを確認しました。実 AI クライアントとホスト環境での検証は未実施です。
