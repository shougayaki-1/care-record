# 本番証跡チェックリスト

初回提供と重要な構成・セキュリティ変更の判定用です。通常のアプリ配備で毎回全項目を取り直す手順は [デプロイ手順](../deployment-runbook.md) に置きません。定期的な復旧試験の周期は [バックアップ・復旧・BCP](backup-restore-bcp.md) に従います。

以下はコードから確認できないため、未提出なら未準拠です。画面キャプチャだけでなく、取得日時、対象Project ID、承認者、設定エクスポートまたはベンダー資料のハッシュを`compliance_evidence`へ記録します。

- [ ] Supabase/Vercel/Googleの契約主体、プラン、データ保管・処理国、再委託先
- [ ] DB/Storageの保存時暗号化、TLS、鍵管理、管理者アクセスログ
- [ ] 12時間完全バックアップ、再試行、14時間鮮度監視、保持世代・論理分離・WORM、直近の月次復旧試験と実測RPO/RTO
- [ ] Authレート制限、セッション、禁止した認証方式、管理者権限一覧
- [ ] 全public/storageテーブルのRLS有効状態、ポリシー、GRANTのカタログ出力
- [ ] Vercel環境変数のスコープ、変更履歴、デプロイ保護、ログ保持
- [ ] 監査アーカイブ受信先のWORM設定、署名検証、復元試験
- [ ] MALWARE_SCAN_URLの可用性、ログ保持、検知試験
- [ ] イベント駆動の鍵交換・緊急失効手順、旧平文Googleトークンが0件であること
- [ ] サービス仕様適合開示書、SLA、委託契約、終了時消去条項
- [ ] 運用責任者、連絡網、年次教育、半年訓練、月次ログレビュー
- [ ] 記録種別ごとの保持年数と法的根拠の専門家確認
- [ ] Critical/High脆弱性0件、SBOM、ペネトレーションテスト
