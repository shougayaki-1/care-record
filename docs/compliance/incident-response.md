# インシデント対応手順

アプリ配備だけの障害は [デプロイ手順](../deployment-runbook.md) の切り戻しを使います。DB破損・データ喪失を伴う場合は [バックアップ・復旧・BCP](backup-restore-bcp.md) に従います。

## 発動と初動

漏えい、改ざん、利用不能、不正アクセス、マルウェア、バックアップ異常、委託先事故を検知した者は直ちに指揮者へ連絡します。Critical/Highでは、証拠を保全しつつ認証情報失効、通信・機能の隔離、外部連携停止など被害拡大防止を優先します。

1. 検知時刻、報告者、影響システムを`security_incidents`へ登録
2. 監査ログ、クラウドログ、デプロイ、DB・Storageのスナップショットを保全
3. 影響する本人、事業所、件数、情報種別、国外・再委託影響を評価
4. 個人情報保護委員会、厚生労働省等への報告要否・期限を専門家と判定
5. 契約SLAに従い顧客へ第一報、定時更新、終報を実施
6. クリーンな環境・認証情報・バックアップから復旧し、侵入継続がないことを確認
7. 原因、対応、影響、再発防止、責任者、期限を事後レビュー

## 訓練

半年ごとに、ランサムウェア、クラウド認証情報漏えい、誤公開、大規模障害のいずれかで机上訓練します。訓練結果はBCP、連絡網、SLAへ反映します。

窓口名、電話、暗号化メール、外部フォレンジック、保険、顧問専門家は本番開始前に非公開連絡票へ記入し、四半期確認します。
