# MCP 確認付きシフト作成（#179）

`propose_shift_create` は本人・事業所・権限と機能設定を検証し、利用者、スタッフ、開始・終了日時を固定した10分間有効の確認待ち案を作る。シフトは作成しない。ユーザーは CareRecord の認証済み画面で内容を確認して登録する。確認時に本人、ブラウザーセッション、元の OAuth 接続、事業所と権限、対象、期限と重複を再確認し、既存のシフト作成 RPC、成功監査、案の消費を同じトランザクションで行う。同じ案の再送は既存結果を返す。Google 同期は DB 確定後に既存処理を試み、失敗や不明の場合はシフトを残して同期状態を表示する。同期の状態は `get_shift_create_result` でも照会できる。

確認前に案が変更できないよう、案の表は非公開 schema に置き、アプリ・MCP ロールの直接アクセスを禁止する。利用者と担当の各1名、24時間以内の1区間に限定する。業務ルールである勤務予定・移動・資格・サービス種別の適合性は確認画面で本人に確認を促し、自動判定しない。重複検査と書込みの間に既存の通常操作が割り込まないよう、確認中は対象テーブルの書込みを短時間直列化する。ロック待ちや競合で失敗した場合、何も登録せず再確認を求める。案は削除せず保持される。

事業所別のシフト作成制御は既定 off。既存のシフト参照と人物検索の制御も必要で、変更系の提供条件や外部 AI の扱いが未承認の事業所では有効にしない。設定の有効化・停止は連携管理権限と確認を要し、設定変更と監査を同一トランザクションで記録する。MCP の配備、実認証試験、事業所での機能有効化は別途行う。

Context7 は利用枠上限のため、2026-10-30 に [Supabase DB 関数](https://supabase.com/docs/guides/database/functions)、[PostgreSQL 17 のロック](https://www.postgresql.org/docs/17/explicit-locking.html)、[MCP ツール仕様](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)、[Next.js 16 のフォーム](https://nextjs.org/docs/app/guides/forms) と同梱資料を確認した。
