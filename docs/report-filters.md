# 実績一覧のフィルター保存

`/app/reports` の利用者ID、記録ステータス、開始日・終了日（空欄を含む）、未承認・差戻しのみ、並び順・並び項目をブラウザの localStorage に保存する。ユーザーID・事業所ID・一覧／帳票ビューごとに分離し、再訪・再読み込み・同じブラウザでの再起動後に復元する。利用者名、記録本文、検索結果、選択チェック、認証・権限情報は保存しない。シフトIDはURLだけの一時条件とする。

初回は所属と利用者一覧の取得後に、URLの明示条件 → 保存値 → 既定値の順で解決してから記録を取得する。事業所・アカウントが画面内で切り替わった場合は、直前の事業所のURL条件を引き継がず、切替先の保存値を読む。不正なJSON、非対応バージョン、不正なフィールドは保存値全体を破棄して既定値に戻す。参照できない利用者IDは「全員」に戻す。ストレージの読書きが拒否された場合もURLによる絞り込みを続けられる。

- 通常の「全件表示」への再訪では、一覧の前回条件を復元する。条件をすべて外すには「絞り込みをリセット」を使う。
- `status=unapproved` は未承認・差戻しモードを明示し、保存された単一ステータスを解除する。期間など未指定の条件は保存値を使う。保存値がない場合は期間を空欄にする。
- `recordStatus` の明示は保存された未承認・差戻しスイッチを解除する。同時に `status=unapproved` があればスイッチを優先する。
- `period=current_month` は日本時間の表示時点の当月を使用し、保存された未承認・差戻しモードを解除する。明示された `status` は優先する。当月モードを保存して再訪した場合も月を再計算する。日付を編集すると当月モードを解除する。
- `view=export` は帳票用の保存値（未保存なら承認済み）を使い、未承認・差戻しスイッチは無効にする。
- 正規化URLには空欄の日付・既定値・`status=all` も含める。Back/Forwardや再読み込み時に、明示した空欄やオフの条件を古い保存値で補完しない。
- リセットは現在のビューの既定値（月初から・終了日なし、一覧は全ステータス／帳票は承認済み）へ戻し、シフト条件も解除して保存値を更新する。

実装: `src/hooks/useReportFilters.ts`。DB、API、RLS、権限定義の変更はない。

技術仕様確認: 2026-10-22、Context7でNext.js（対象16.3.6）の `useSearchParams` / `router.replace`、zod（対象4系）のISO日付検証とオブジェクトの未知フィールド除去を確認。Next.jsの同梱ドキュメントも参照した。
